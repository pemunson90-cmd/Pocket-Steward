# ARCHIVE-01 integration

Claude supplied `archive-01-return.zip` against source commit `f34b9502fe280ee759b32ff02e66ff03b8899a1a`. Original contribution: https://github.com/pemunson90-cmd/Pocket-Steward/commit/5c19950ed6f963f5b6fcc3b15ae44135acbad950. The focused binary patch applied cleanly; all 23 supplied fixture hashes match. The external verification harness is not part of the Android app.

The app now reads RAR4/RAR5 and plain or LZMA/LZMA2/Copy-compressed 7z headers, leaving archives intact. Inspection reads at most 8 MiB of headers, decodes at most 8 MiB of header data, visits at most 20,000 RAR blocks, counts at most 2,000 entries and retains 40 names of at most 500 characters. Nonseekable sources stage at most 64 MiB of compressed data in a uniquely owned private-cache file and remove that file on normal, failed or cancelled exits. Encryption, multipart, damaged, truncated and unsupported formats report explicit incomplete coverage. These names are evidence, never extraction paths or mutation authority.

XZ for Java 1.10 (0BSD) decodes 7z headers; Commons Compress 1.28.0 is unchanged. There is no unRAR library or native archive dependency. RAR4 compact Unicode names use a name-codec implementation; non-Unicode OEM names may display imperfectly. The fixtures contain synthetic content only; their generation instructions, tool versions and hashes are retained with them.

Integration adds coroutine cancellation callbacks to Filing, metadata review and the shared inspector, including sampling/cache reads and writes. Cancelled requests propagate cancellation. Parser cursor/stream reads poll cancellation; nonprogressing reads fail instead of spinning. RAR5 unsigned integer overflow is rejected. Android-incompatible HotSpot allocation-counter references in tests are accessed through reflection on the host JVM. The header-flood test builds its input linearly. Review displays an unavailable member listing explicitly rather than “at least 0 entries.” Archive cache derivation revision 2 invalidates old archive observations without discarding unrelated metadata.

The targeted Android-project run passed all 35 archive/metadata/filing tests, including API36 Robolectric provider-descriptor integration, cancellation without partial cache publication, nonprogressing sources, real fixtures, resource-budget counters, corruption/truncation fuzzing and the filing engine. Claude's separate 30-test JVM run is attribution, not a substitute for app checks. The combined app run passed all 854 host tests, lintDebug (no errors), Android test compilation and dependency dex compilation. Phone/provider acceptance remains open in the completion register.

Limitations remain explicit: self-extracting signatures, RAR1.4, sibling multipart volumes, encrypted headers, external 7z names and unusual header filter chains are unsupported. A process killed during staging can leave that owned private-cache file until cache reclamation. Real provider pipe/virtual-document behavior, process death, storage pressure and phone memory/thermal measurements still require device acceptance. No APK checkpoint, version bump or signing change is included.
